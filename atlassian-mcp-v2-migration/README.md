# Atlassian MCP v1 to v2 migration

## Scope
Replace every `https://mcp.atlassian.com/v1/mcp` and `/v1/sse` endpoint with `https://mcp.atlassian.com/v2/mcp`.

## Audit result (25 November 2026)
13 v1 references found across 12 org-synced plugins: sales, productivity, enterprise-search, product-legal (SSE), human-resources, design, legal, product-management, data, brand-voice (config and README), operations, engineering.
The Daemon plugins (daemon-engineering, daemon-pir, daemon-pm) contain none.
The claude.ai Atlassian connector already exposes the v2 toolset.

## Why the org copy cannot be fixed by a local edit
These plugins come from the Anthropic catalogue marketplace (`knowledge-work-plugins`) and are re-synced from the server. Local edits are overwritten.

## Steps
1. Local machines and Claude Code installs, run in a terminal:
   `./migrate.sh` (dry run), then `./migrate.sh --apply`. It verifies that no v1 references remain.
2. Org-wide (you are admin): run `./build-patched-plugins.sh <new-empty-folder>` on your own computer. It creates 12 patched `<plugin>-daemon` folders from your synced copies. In Claude Code on that computer, ask it to publish each folder to the organisation (publishing is not offered in cloud sessions). Then approve, install for everyone and hide the originals as below. Alternatives:
   - Publish an org-owned copy of each affected plugin with the patched `.mcp.json` (run the script on the plugin source), set it to "installed" and hide the catalogue versions.
   - Raise the v1 endpoints with Anthropic as a catalogue defect.
3. Users re-authenticate Atlassian once (`/mcp`) after the endpoint changes.
4. Re-run the dry run after each sync to confirm no v1 endpoints return.

## Known limitations
- Tested on copies of the synced plugins only. The scripts have not been run against live org plugin installs.
- The claude.ai Atlassian connector sign-in was checked on 25 November 2026 (v2 toolset, site reachable). The patched plugin `.mcp.json` entries have not been signed in yet; test after the `-daemon` plugins are published.
- Publishing to the organisation is not offered in cloud sessions. It must be done from a computer or the Claude app.
- Patched copies are built from the public Apache-2.0 upstream repos (knowledge-work-plugins, claude-for-legal), so the org-synced versions may differ slightly (versions, org-specific edits). Compare before publishing.
- Does not change plugin settings stored server-side.
